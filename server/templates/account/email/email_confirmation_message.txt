Overrides allauth's own email_confirmation_message.txt.

The stock text opens "You're receiving this email because user <name> has
given your email address to register an account on <domain>." That sentence is
written for the *minority* case — a stranger typing someone else's address into
the signup form — and so it talks about the reader in the third person. For the
overwhelmingly common case, where the reader signed up a minute ago, it reads
like the site discussing them with somebody else.

The username is dropped entirely, which is also what most services do. The
argument for keeping it is that it would distinguish a stranger's signup from
the reader's own forgotten one — but that does not survive the case it is meant
to serve. The way a stranger receives this mail is a mistyped address, and to
that reader the username is a name they have never seen attached to an account
they cannot reach; it tells them nothing they can act on. The legitimate reader,
meanwhile, is looking at the browser tab that just asked them for a code, and
does not need to be told who they are. So it discloses a little to the wrong
person and helps the right person not at all.

What the stock text lacks is the sentence that whole defensive framing exists
to support: what to do if it wasn't you. Saying "ignore this" is only
reassuring alongside the reason it is safe to ignore, so the last line gives
both.

These are new msgids with no catalog behind them, which is deliberate and not
an oversight: L10N.md ("allauth emails are English", §on server-side strings)
settles that these mails are not translated. The blocktranslate tags are kept
anyway so the strings stay extractable if that decision ever changes.

The `code`/`activate_url` branch is preserved from the stock template. Code
verification is on today (ACCOUNT_EMAIL_VERIFICATION_BY_CODE_ENABLED), but
dropping the link branch would turn flipping that setting into a silently
broken email rather than a setting change.
{% endcomment %}
